Démonstration

Ci-dessous, le widget hors de Grist : il se rabat sur un jeu d'exemple auquel on a ajouté des colonnes de tous types (texte long, nombre, booléen, choix, liste de choix, référence, date, date-heure, lien, colonne formule). Cliquez sur une tâche, puis faites défiler le panneau jusqu'à « Tous les champs ».

Ce que ça ajoute

Section « Tous les champs »

Une ligne par colonne réellement présente dans Tasks, avec son libellé Grist, son type, et l'éditeur qui va avec. Filtre par nom, masquage des champs vides, masquage des champs déjà édités plus haut.

Champs dans la liste

L'étoile ★ d'un champ — ou le bouton ⚙ Champs au-dessus de la liste — l'affiche en puce sous le nom de chaque tâche et dans l'info-bulle de sa barre.

Export CSV complet

Les tâches visibles × toutes leurs colonnes, séparateur ; et BOM UTF-8 : le fichier s'ouvre directement dans Excel ou LibreOffice.

Colonnes ajoutées en cours de route

Une colonne créée dans Grist pendant que le widget est ouvert ? Le bouton ↻ relit le schéma. Aucune configuration à tenir à jour.

Mode opératoire

  1. Ajouter le widget. Dans votre document : Ajouter un widget → Custom, source de données Tasks. Collez l'URL ci-dessus dans le champ URL du panneau de droite.
  2. Donner l'accès complet au document. Access level → Full document access. Sans lui, Grist n'autorise ni la lecture des métadonnées de colonnes, ni l'écriture dans une colonne inconnue d'avance.
  3. Laisser la table telle qu'elle est. Les colonnes du schéma TaskFlow manquantes sont ajoutées ; vos colonnes à vous sont conservées et détectées. Le Gantt a seulement besoin de titre, dateDebut et dateEcheance pour dessiner les barres.
  4. Ouvrir une tâche, faire défiler jusqu'à Tous les champs, modifier. L'écriture part dans Grist quand le champ est validé ou quitté.
  5. Épingler ce qui compte avec ★ pour le voir dans la liste et l'info-bulle sans ouvrir le panneau.

Instance auto-hébergée : pour retrouver le widget dans le sélecteur « Custom Widget », démarrez Grist avec GRIST_WIDGET_LIST_URL=https://nicolasmrsn.github.io/gantt-tous-les-champs/manifest.json.

Comment c'est fait

La modification est purement additive : aucune fonction du widget d'origine n'est réécrite. Un bloc CSS et un bloc JavaScript sont insérés dans le fichier amont, et le module s'installe en enveloppant quatre fonctions existantes (renderPanel, renderTaskList, loadAllData, useDemoMode). Si une étape échoue — droits restreints, métadonnées illisibles, version de Grist différente — le widget continue de fonctionner comme avant, et se rabat sur les colonnes lues dans les données.

Le dépôt contient le fichier amont tel quel, les deux blocs ajoutés, et le script de construction : python3 src/build.py régénère le widget. Un diff entre le widget et l'amont ne montre que ces deux blocs.
